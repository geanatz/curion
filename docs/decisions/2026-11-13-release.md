# Curion 0.3.7 release and maintenance decisions — 2026-11-13

**Status:** Owner-approved for the specific Curion 0.3.7 release and subsequent manual-release workflow.

**Authority:** Explicit owner approvals in the Curion project conversation on 2026-11-13/14; execution evidence is linked below.

**Scope:** Current stable MCP product, security, documentation, testing, and release automation. This is not blanket authorization for future destructive changes or provider spending.

## Accepted decisions and rationale

1. **Preserve the public interface.** Exactly two MCP `stdio` tools remain available: `remember(text)` and `recall(text)`, with strict input and projected output schemas. Avoid expanding functionality as part of stabilization.
2. **Protect newly created Windows data directories.** Apply native protected NTFS ACLs before writing new project-memory, trace, configuration, and registry data; fail safely if protection cannot be installed. Existing Windows stores are **not migrated or rewritten automatically** because their access policy may be intentional. Legacy assessment/remediation remains an opt-in follow-up ([Issue #8](https://github.com/geanatz/curion/issues/8)). This supersedes relying on POSIX permission modes on Windows.
3. **Keep provider access out of automated verification.** Use isolated synthetic stores and deterministic MCP tests. A Codex CLI `recall` handshake was actually run. Real Claude Code login and real third-party provider integration tests were deferred; no completion claim should be made for them.
4. **Security and compatibility before npm release.** Update vulnerable dependencies and verify the actual shipped dependency graph, including Zod 4 compatibility and the optional local semantic-embedding path. Report audit results with their date rather than claiming permanent immunity.
5. **Use one manual release gate.** The `publish.yml` workflow stays `workflow_dispatch`-only on `main`, requires a matching version plus explicit `PUBLISH` confirmation, runs Ubuntu/macOS/Windows checks, and publishes the npm package with OIDC provenance.
6. **Keep npm the primary install channel, GitHub Releases the human-readable release history.** Git tag `vX.Y.Z` identifies the published source commit; GitHub Release notes come from the matching `CHANGELOG.md` section, with no duplicate package archives. For releases after 0.3.7, the workflow creates the GitHub Release **only after** successful npm publication, with scoped `contents: write` permission and an existing-tag SHA guard.
7. **Simplify user documentation.** The root README is an intentionally short onboarding guide; detailed configuration, client setup, storage privacy, tool contracts, and decisions have distinct authoritative pages under `docs/`.
8. **Protect experimental and historical work.** Do not merge the adaptive-recall experiment [PR #1](https://github.com/geanatz/curion/pull/1) without separate product approval. Preserve dirty worktrees and real `.curion/` data during maintenance.

## Verified results at this decision checkpoint

- Curion `0.3.7` was published as npm `@geanatz/curion@0.3.7` on 2026-11-13 UTC, with attested provenance. Source commit: `96ce011cdcb93ea637bbfe8fa18a59bc75735af6`.
- [GitHub Actions publish run 43494099575](https://github.com/geanatz/curion/actions/runs/43494099575) succeeded on all three operating systems and published npm. An isolated installation directly from the registry was performed successfully on Zenith.
- The annotated `v0.3.7` tag points to that same source commit. [GitHub Release v0.3.7](https://github.com/geanatz/curion/releases/tag/v0.3.7) was published **after npm**, retroactively; the old package was **not** republished.
- The `publish.yml` improvement was merged separately through [PR #12](https://github.com/geanatz/curion/pull/12), at `74985c25d9f2781bfc1b0ebbf3b8fc2d647936b5`. YAML checks and four mocked flow scenarios passed on Zenith. **The new automatic GitHub Release step has not yet been exercised in a real subsequent npm release.**
- The 0.3.7 candidate's production `npm audit --omit=dev` found **zero known advisories at verification time**. Tests passed locally and in release CI; this does not establish safety for future dependency advisories or untested third-party providers.

## Still open / requiring fresh approval

- [Issue #8](https://github.com/geanatz/curion/issues/8): legacy Windows-directory permission inspection and any separately authorized data-preserving remediation.
- [Issue #6](https://github.com/geanatz/curion/issues/6): optional deterministic offline MCP success-path E2E coverage.
- Real Claude Code / third-party provider smoke tests remain deferred.
- A new GitHub Release automation run can only be verified when a future, independently approved npm version is published; never rerun `npm publish` merely to test release-note automation.
- Existing project-specific or shared-user data, destructive worktree cleanup, provider charges, and experimental feature activation require their own explicit permissions.

The [older maintenance decision record](2026-11-12-maintenance.md) documents earlier scope-limited "no npm publish" approval. Its restriction was superseded **only** by the later explicit 0.3.7 publication approval; it is not an active prohibition or standing release permission.
